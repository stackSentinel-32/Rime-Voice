Turn-versioned voice booking agent — stale tool results never spoken, never written

The claim under test

When the user interrupts during agent speech or a pending tool call, queued Rime audio stops in <300 ms, the stale tool result is discarded — never spoken, never written to the DB — and the agent's next utterance and the final DB state reflect only the latest request.

Scenario: agent looks up booking 12 (Thursday) with an artificially slowed tool call → you interrupt mid-flight asking for Friday → v1→v2, audio cancels, fresh update dispatches, the stale lookup returns late and is discarded_stale. Runs the real orchestrator (agent/turn_manager.py) against this deployment's DB.
